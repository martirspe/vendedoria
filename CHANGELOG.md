# Changelog

## [Unreleased]

### Added
- Web store as an add-on (`store` integration): the sales agent is the core product and the store is turned on from Integraciones only by businesses that need it. Included from Crece up and in the trial; Inicia and expired plans do not include it, so the store goes offline and the console shows "disponible desde el plan Crece" with a link to Planes. While it is off the store answers 404 on its subdomain and custom domain (catalog, product pages, sitemap and checkout included), store settings cannot be saved, published or previewed (`403`; unpublishing still works), the console hides Tienda web, Cupones, the "Visible en tienda" switch and the "En tienda web" badge. The sales agent keeps selling in chat exactly the same (catalog search, photos, prices, stock, orders and Mercado Pago payment links do not depend on the store); it only stops adding store links. Each add-on keeps its own switch and settings: custom domain and Meta Pixel/GA4 run on the store, so they need it on first (`requires` in `GET /integrations`) and while the store is off they are paused (`enabled: true`, new `active: false`; "En pausa" in the console) and resume by themselves with their domain and IDs when the store is turned back on. Instagram and Team never depend on it. Catalog, orders, coupons and store settings are kept, so turning it back on restores the store as it was. New businesses start with it off; migration `0003_store_integration` turns it on for every business that already has a store
- Payment confirmation to the buyer: when an order linked to a chat is paid (Mercado Pago webhook or marked paid in Pedidos), the buyer gets "¡Recibimos tu pago…! Tu pedido … quedó confirmado" on the same WhatsApp or Instagram chat, exactly once per order and only inside Meta's 24-hour window; it shows in Mensajes as a seller message. Sending goes through the new shared `ChannelMessengerService`
- Buyer return page after paying a chat order: Mercado Pago now returns to `/payment/success|pending|failure` (public, prerendered, `noindex`) instead of the console login, with a short status message and the hint to go back to the conversation. The page shows no order or business data taken from the URL
- Envíos (`/app/shipping`, `GET/PATCH /shipping`, `GET /shipping/ubigeos`): delivery modes, courier rates by distance, free shipping and pickup are business settings, available on every plan with or without the web store. The sales agent uses them before the payment link: it asks the buyer's district (offering pickup when available; same-name districts are disambiguated by province), quotes the cheapest configured courier with the free shipping threshold applied, and creates the order with `shippingCents` and the same delivery record as web orders, so the Mercado Pago link charges products plus shipping and the reply shows the breakdown. A message with a street number is kept as the delivery address; otherwise the buyer is asked for it after paying. With no delivery mode configured, no shipping is charged and the agent says delivery is coordinated in the chat. The playground and Mensajes show the new "Envío" step
- Catalog import from the console (Productos → Importar catálogo, `/app/products/import`, owner or admin): drop the package folder (`catalog.json` plus `images/`) and review what will happen before anything is saved: new and existing products, sets, what goes live on the web store, photos still to upload, plan quota and row-level errors or warnings (`POST /catalog/import/preview`). Importing uploads only missing photos through the normal media pipeline (WebP, S3 + CloudFront; `POST /catalog/import/media`) and writes products, photos and set pieces in one transaction (`POST /catalog/import`), so a failed import changes nothing. Re-importing updates texts and photos, skips photos already uploaded (matched by SHA-256, new `ProductMedia.sourceHash`, migration `0002_product_media_source_hash`) and keeps the price, stock and publication set in the console unless the merchant opts in to overwrite prices or stock. Optional "full catalog" mode unpublishes store products missing from the file or inactive in it (nothing is deleted), and an optional `store` block in the package applies template, free shipping, shipping origin, courier rates and store images without replacing what is already set. The Selecta seed data carries its store settings in that block, and the seed script stays a development tool
- Platform operators for VendedorIA staff, the base for the future global operations console: `SUPERADMIN` and `ADMIN` live in `User.platformRole`, separate from business memberships (a business `ADMIN` gets no platform access). They are granted, changed or revoked only with the `create-admin` CLI (`npm run create-admin -w @vendedoria/api`): the password never goes in argv, operator passwords need 12+ characters with letters and digits, the last `SUPERADMIN` cannot be demoted, password changes end every session and role changes end the platform sessions. Platform sessions are separate from business ones (`POST /platform/auth/login` with rate limit and Turnstile action `platform-login`, `POST /platform/auth/refresh`, `GET /platform/me`; 10-minute access tokens with their own audience and 12-hour refresh tokens): neither token nor refresh token works on the other side, and the role is read from the database on every request, so revoking it cuts access at once. Routes require permissions, not roles (`@PlatformPermissions('tenants.read')`): `SUPERADMIN` holds all of them; `ADMIN` reads businesses, billing (flow A), metrics and audit, suspends stores and opens support assists, but cannot change plans, manage operators or platform credentials, or delete businesses. Login and `GET /platform/me` return the operator's permissions so the console shows only allowed actions; a future role is one enum value plus one entry in `ROLE_PERMISSIONS`. Grants, role changes, revocations, password resets and platform logins are recorded in `PlatformAuditLog`. Migration `0017_platform_operators`
- Sales agent sells with an expert method in every chat: connect, understand the need with one question at a time, recommend 1 to 3 catalog options with a reason, handle objections with catalog and FAQ facts, close on buying signals with one concrete next step and offer at most one complement after the yes. Ethical sales psychology is built in (no fake urgency, invented scarcity or testimonials, no pressure after a "no"); "quedan pocas unidades" is only said when stock is 5 or less
- 13 switchable sales techniques grouped by stage (discover, persuade, close), an objections playbook written by the merchant and four starting profiles (consultive advisor, friendly expert, premium specialist, quick close) that set tone, style and techniques in one click. Existing agents start with discovery, benefits, objections, alternative close and cross-sell on
- Advanced prompt mode per agent: guided (compiled from the form) or a full custom prompt up to 12 000 characters, with "start from the guided prompt" and a read-only view of the final instructions (`GET /agents/:id/prompt`). Hard limits, WhatsApp formatting and catalog, stock and payment-link truth always apply on top of a custom prompt
- Several sales agents per business (up to 10): create from scratch or copying the current one, switch, delete (not the primary), and assign the channels each one answers (`GET/POST /agents`, `GET/PATCH/DELETE /agents/:id`, `PUT /agents/:id/channels`). Channels without an agent are answered by the primary agent; the playground tests the selected agent.
- Integraciones turns plan features on and off; each one shows its page in the console sidebar only while it is on and included in the plan (`GET /integrations`, `POST /integrations/:key/enable|disable`, owner or admin). Pages explain how to turn it on, or which plan includes it, when it is off.
- Custom domain (Crece and up): the merchant sets `www.sumarca.pe`, gets the CNAME (and TXT when needed) to create and checks it (`GET/PUT/DELETE /integrations/custom-domain`, `POST /integrations/custom-domain/verify`). Certificates are issued by Cloudflare for SaaS (`CLOUDFLARE_SAAS_ZONE_ID`, `CLOUDFLARE_SAAS_API_TOKEN`, `CUSTOM_DOMAIN_CNAME_TARGET`); outside production domains activate without it. Once active the store answers on the domain, its subdomain redirects there (302), and the agent links, store URL and Turnstile hostname check use it. nginx gets a default server for verified store domains
- Meta Pixel and GA4 in the store (Escala and up, `PUT /integrations/tracking`): nothing loads until the buyer accepts the new cookie banner (accept and reject with the same weight, decision can be changed from the legal pages); events page view, view item, add to cart, begin checkout and purchase (once per order, only when paid). The cookie policy lists `_ga` and `_fbp` only for stores that use them, and the CSP allows the Google and Meta hosts
- Instagram Direct (every plan): connect a professional account with its token (`GET /channels/instagram`, `POST /channels/instagram/connect`), signed webhook `GET/POST /webhooks/meta/instagram` (`INSTAGRAM_APP_SECRET`, falls back to `META_APP_SECRET`); the same sales agent answers DMs (text, replies split at 1 000 characters) and operator replies from Mensajes go back to Instagram. An account can only be connected to one business
- Team (Crece and up): invite people as admin or advisor with a single-use link valid for 7 days (only its hash is stored), change roles, remove members and cancel invitations (`/team`, public `GET/POST /team/invites/accept/:token` with rate limit and Turnstile); members plus pending invitations count against the plan's users. Console page `/invite/:token` creates the account and signs in
- Prepay and chat packs on the Plans page: pay 1, 3, 6 or 12 months at once with 0 / 5 / 10 / 17 % off (one payment, the days are added at the end of the current period), and buy 100, 500 or 1 000 extra chats for the current month (S/ 15, S/ 65, S/ 125; paid plans only)

### Security
- Cloudflare Turnstile on login, sign-up and store checkout (`TURNSTILE_SITE_KEY` + `TURNSTILE_SECRET_KEY`): the widget runs in Managed mode and only appears when Cloudflare needs an interaction; the API redeems each single-use token with Siteverify after the per-IP rate limit and checks the action and that it was solved on the console or on that same store. If Cloudflare cannot be reached the request is refused (503) instead of skipping the check. Without the keys the forms keep working with rate limits only. Deploy: create a Managed widget with the console host and `STORE_BASE_DOMAIN` as hostnames and set both variables; Cloudflare test keys are rejected in production
- Meta WhatsApp webhook: the signature is now checked over the exact raw body (re-serialized JSON broke valid signatures with accents or emojis), and in production a missing `META_APP_SECRET` rejects every inbound message instead of accepting unsigned ones. Deploy: set `META_APP_SECRET` before enabling WhatsApp
- The mock checkout page (`/payments/mock-checkout/:id`) answers 404 in production, like the payment simulator
- Dependencies: Angular 22.2.1 (store pins aligned with the console), `find-my-way`, `qs`, `fast-uri` and `brace-expansion` patched; `@fastify/static` 10 (required by the updated Nest Fastify adapter; with 9 the API failed to start); `npm audit --omit=dev` down from 13 high to 4 high, all requiring major upgrades (Nest 12 for Fastify, Prisma)
